## 项目一：百度 · 慧播星 AI 视频生成

> **时间**：2025.12 - 2026.03 | **技术栈**：Go + Gin + MySQL + Redis + K8s + LLM
> **详细参考**：[[../../简历与项目/项目总览与详细总结.md#项目一百度--慧播星-ai-视频生成平台|项目总览-百度]]

### 1. 多 Agent 间怎么协同/通信？（🔥 最高频！几乎所有公司都问）

**被问公司**：腾讯(×3) · 美团 · 字节 · 币安 · 京东 · 美图

**回答要点**：
- 核心：通过 **Job 表（数据库）** 作为唯一事实源
- Agent 之间不直接发消息，而是读写共享的 DB 状态
- Brain Agent 把分解后的子任务写到 Job 表不同字段
- 子 Agent 感知到自己负责的状态变更后执行并写回结果
- 类似 Shared State 模式，而非消息传递

**面试官可能追问**：
- "这是 Agent 还是 Workflow？" → 承认偏 Workflow（固定的 DAG 流程）
- "主 Agent 是协调还是实际干活？" → 主要是协调调度，资源紧张时也参与处理
- "子 Agent 之间直接通信好还是通过主 Agent 中转好？" → 通过主 Agent 更可管控，但增加延迟和单点

### 2. 节点执行失败怎么处理？

**被问公司**：腾讯(×2) · 美团 · 美图 · 币安

**回答要点**：
- 每层都有失败处理：
  - 单个 Operator 失败 → 重试（幂等设计）
  - 连续重试失败 → 标记任务失败，告警
  - DAG 节点不可跳过 → 整个任务失败，人工介入
  - DAG 节点可跳过 → 跳过继续执行后续节点
  - 三层补偿机制：回调驱动 + 查询时推进 + Cron 定时兜底
- 最终失败：告警 + 人工排查

### 3. 这个系统的并发量是多少？QPS 大概多少？

**被问公司**：腾讯 · 腾讯(5.6)

**回答要点**：
- 日产能：3000 条视频/天
- QPS 不大（视频生成是长耗时任务，非高并发）
- 但 API 调用量很大（生成一条视频要调多次 LLM + 多次素材检索）
- 四层流控的核心目标不是提高 QPS，是**保护后端服务不被突发流量打垮**

### 4. 四层流控/防护体系详细说明（🔥 高频！）

**被问公司**：字节 · 腾讯 WXG · 美团 · 美图(×2) · 腾讯(5.6) · 飞轮数据 · TapTap

**回答要点**：
1. **BRCC 动态配置**：配置中心调整并发阈值，不重启
2. **Redis Hash 并发池**：每任务类型维护计数器，限制并行数
3. **Redis SETNX 互斥锁**：防止同一个任务被多个 Worker 处理，心跳续期
4. **外部排队**：渲染服务自身排队机制做兜底

**追问准备**：
- "锁丢失了怎么办？" → 三层兜底：锁续期 + 超时后其他 Worker 可接 + 定时扫补偿
- "心跳续期怎么做？" → 后台线程每 1/3 超时时间续期一次
- "怎么判断任务已经死亡？" → 心跳超时未续期 → 释放锁，其他 Worker 重新获取

### 5. AI 脚本仿写的阶段流程

**被问公司**：美团 · 美图 · 飞轮数据 · TapTap

**回答要点**：
- 四阶段 DAG：预处理（搜索+参数解析）→ 参考提取 → 结构生成 → 润色
- 用户可上传参考脚本 → 系统提取风格特征
- 用户没上传时通过 RAG 从库中匹配相似脚本
- 阶段结果持久化到 Job 表（可恢复、可追溯）

### 6. 日产 3000 条，做了哪些优化？

**被问公司**：TapTap

**回答要点**：
- 四层流控防止并发打爆后端
- DAG 可恢复：中间结果持久化，崩溃后可续跑
- 素材跨供应商并发搜索 + 容错（部分失败不影响整体）
- 渲染提交异步化，配合回调推进

### 7. 这个多 Agent 系统有多少个 Agent？

**被问公司**：腾讯 · 腾讯(5.6)

**回答要点**：
- 编导大师系统：6 个 Agent（编导大脑 + 综合素材 + 素材检索 + AI 生图 + 泛图表 + 图生视频）
- 脚本生成是 DAG Operator（不是独立的 Agent）

### 8. Diffmode / 代码变更影响分析

**被问公司**：美团（一面有涉及）

**回答要点**：
- 输入：代码变更 + 需求 ID → 分析影响哪些 API → 推送给 QA 生成测试用例
- 多层匹配：精确 URI → 前缀匹配 → MySQL 兜底

## 项目二：华为 · 云桌面运维管理平台

> **时间**：2025.07 - 2025.09 | **技术栈**：Java + Spring Boot + MyBatis + Redis + Apollo + TaskFlow
> **详细参考**：[[../../简历与项目/项目总览与详细总结.md#项目二华为--云桌面运维管理平台|项目总览-华为]]

### 1. 桌面升级的完整链路是怎样的？（🔥 高频！）

**被问公司**：腾讯 WXG · 美团 · 美图 · 币安 · TapTap

**回答要点**：
- 用户上传 Excel（桌面列表）→ 系统校验（存在性/租户策略/动态池过滤）
- 导入数据版本化存储（MVCC 风格）
- 定时任务扫描生效版本的桌面列表 → 增量分批下发
- 每批调用 WDM API 执行升级 → 记录任务状态
- 升级前创建快照 → 失败可回滚
- 反馈升级结果

### 2. 数据库索引怎么设计的？

**被问公司**：腾讯 · 美团 · TapTap

**回答要点**：
- 高频查询字段：`task_id`、`import_version`、`status`、`desktop_id`
- 联合索引：`(task_id, import_version)` 定位版本化的导入批次
- `(status, create_time)` 定时任务扫增量
- 索引设计考量：区分度、查询频率、写入开销
- 索引太多的问题：写入变慢、占用空间、优化器可能选错

### 3. 分批下发怎么做？防止重复下发？

**被问公司**：腾讯 WXG · 美图 · 币安

**回答要点**：
- 每次触发处理 `maxTaskNumber` 台
- **分布式锁**（@DistributionLock）防止多实例并发执行同一批
- **CAS 版本号**（updateVersion）防止锁释放后执行过期任务
- MVCC 版本控制：`effectVersion` 支持热切换

### 4. 升级失败了怎么处理？

**被问公司**：美图 · 币安 · TapTap

**回答要点**：
- 升级前创建快照 → 失败后恢复快照
- 有重试机制（配置重试次数）
- "假失败"修复：超时后主动向 WDM 二次确认快照是否存在
- 最终失败 → 标记失败，告警，人工介入

### 5. 怎么获取下游的升级状态？

**被问公司**：币安

**回答要点**：
- 调用 WDM API 查询升级结果
- 回调 + 查询两种方式获取状态
- 心跳检测判断 Agent 是否存活

### 6. 这个系统你觉得有哪些优化点？

**被问公司**：币安

**回答要点**：
- 目前的自适应分批（基于字符长度 20,000 字符，防止 URL 超长）
- 假失败修复（快照超时后二次确认，成功率 +15%）
- 动态调度（SchedulingConfigurer + Apollo 热更新）
- 后续可优化：消息队列替代定时轮询、升级灰度面逐步放量

### 7. VAG 虚拟网关批量升级回退的架构设计

**被问公司**：腾讯 WXG · TapTap

**回答要点**：
- 3 种升级策略 × 2 种资源池 = 6 条 TaskFlow 编排路径
- 零停机：会话迁移 → ELB 排空 → DNS 移除 → AD 刷新
- 最小保留校验（至少保留 1 个正常节点）
- 回退：升级失败 → 回滚到升级前的快照状态

### 8. 怎么做限流/熔断？避免大量终端同时请求？

**被问公司**：腾讯 WXG

**回答要点**：
- 增量分批下发（每次 maxTaskNumber 台）
- 分布式锁防止并发
- 自适应分批：按字符长度分批调用 WDM，防止 URL 超长

### 9. 多实例部署怎么处理？

**被问公司**：美图

**回答要点**：
- 分布式锁（Redis）防止多实例并发执行同一任务
- CAS 版本号防止过期任务执行
- 幂等设计：同一个任务多次执行结果相同

### 10. 代码质量管理怎么做？

**被问公司**：币安 · 美图

**回答要点**：
- 华为：严格的 Code Review 流程 + 静态代码扫描
- 百度：代码规范 + Review + 测试

## 项目三：OpenROAD-Agent · EDA 芯片设计代码生成

> **时间**：2026.03 - 2026.05 | **技术栈**：Python + PyTorch + Qwen2.5-Coder + LoRA + RAG
> **详细参考**：[[../../简历与项目/项目总览与详细总结.md#项目三openroad-agent--eda-芯片设计代码生成|项目总览-OpenROAD]]

### 1. 这个项目最重点的/最大的难点是什么？（🔥 高频！）

**被问公司**：Meshy · 币安 · TapTap

**回答要点**：
- **上下文管理**：EDA 领域知识多、脚本长，不能全部塞进上下文
- **分层运行时上下文**：Memory / Tools / Skill Brief / Full Skill / Current Design Facts
- **安全性**：生成的代码可能包含危险操作，需要 AST 静态验证 + 风险分类 + 路径白名单
- **RAG 知识库构建**：192 个 API 文档 + 657 个代码模板 → 混合检索

### 2. 长期记忆和短期记忆怎么实现的？（🔥 高频！）

**被问公司**：币安 · 京东 · TapTap

**回答要点**：
- **Session Memory**：当前会话临时记忆（JSON 文件）
- **Project Memory**：跨会话持久化的项目状态（flow_state、decisions、references）
- **Experience Memory**：错误-修复配对（Markdown + frontmatter）
- **Artifact Memory**：运行产出索引
- **Training Feedback**：RL 训练样本
- 设计原则：记忆存历史决策和经验，**不存当前设计状态**（必须实时发现）

### 3. 上下文太长、指令跟随有问题怎么优化？

**被问公司**：京东 · 币安 · Meshy

**回答要点**：
- 分层加载：按需加载不同层级的上下文（Memory/Tools/Skills/Facts）
- 渐进披露：先给摘要，需要时再给完整内容
- 向量检索替代全文传入：只检索与当前任务相关的 Top-K 条
- 运行时 Token 预算管理（budget.py）
- 消息摘要：LLM 压缩早期对话

### 4. Skill 框架怎么设计的？

**被问公司**：币安

**回答要点**：
- 每个 Skill = SKILL.md 文件：场景描述 + 方法论步骤 + API 规范 + 常见陷阱
- 按需披露：运行时只加载与当前任务相关的 Skill 摘要
- skill_recall：需要时再加载完整 Skill 内容
- 避免不相关的 Skill 信息污染上下文

### 5. Memory 和 Current Design Fact 冲突时，谁优先？

**被问公司**：TapTap

**回答要点**：
- **Current Design Fact 优先**——因为设计状态是实时发现的
- Memory 存的是"历史决策和经验"，可能已经过时
- 当前物理状态（instances、nets、core_area）必须从 OpenROAD 实时查询
- 这是 Memory 系统的核心设计原则：防止过期记忆污染执行

## 通用项目问题（所有项目）

### 1. 项目中遇到的最大挑战是什么？（🔥 高频！多公司问）

**被问公司**：腾讯 · 飞轮数据 · TapTap · 腾讯WXG

**回答准备**：
- **推荐选一个"小而有力"的挑战**，不要太大路货
- 好的结构：背景 → 困难 → 你的方案 → 量化成果
- 例子：快照假失败修复（成功率 +15%）、四层流控（从无序到日产 3000）、记忆与事实冲突处理

### 2. 怎么体现你的实力和价值？

**被问公司**：美图

**回答要点**：
- 华为：索引优化提升了查询性能、假失败修复提升了快照成功率
- 百度：四层流控支撑了日产 3000 条视频、DAG 架构提升了系统的可恢复性
- OpenROAD：三阶段训练把成功率从 34% 提升到 76%

### 3. 跨团队沟通——平时怎么找下游团队？

**被问公司**：币安

**回答要点**：
- 先自己在文档和代码中找答案
- 再有针对性地提问（准备好问题和背景）
- 保持良好的文档记录和进度同步

### 4. 代码质量管理怎么做？

**被问公司**：币安 · 美图

**回答要点**：
- Code Review 流程
- 静态代码扫描
- 单元测试
- Agent 场景下：AST 静态验证 + 风险分类 + 执行沙箱

### 5. 有参与实际上线部署吗？

**被问公司**：人马文化

**回答要点**：
- 百度项目是线上真实系统（K8s 部署，3 副本滚动更新）
- 华为项目也是生产代码
- Agent 项目是研究性质，在实验室环境验证

### 6. 前端报错怎么排查？

**被问公司**：币安

**回答要点**：
- 看浏览器控制台（Network/Console）
- 看后端日志（请求参数、异常堆栈）
- 看链路追踪（如果有）
- 复现问题 → 缩小范围 → 定位根因

### 7. 怎么保证两次一样的输入输出一样（LLM 一致性问题）？

**被问公司**：飞轮数据

**回答要点**：
- LLM 本身输出不保证确定（temperature > 0）
- 方案：temperature = 0（确定性最高）、结果后处理做标准化
- 关键路径加后校验（验证输出格式和内容）

### 8. 单元测试会写吗？

**被问公司**：币安

**回答要点**：
- 写过（OpenROAD-Agent 27 个 pytest 测试）
- Agent 的测试难点：生成的代码不确定 → 用执行结果是否通过来验证
- 不直接限制 Agent 发挥，而是提供约束条件 + 验证环节
