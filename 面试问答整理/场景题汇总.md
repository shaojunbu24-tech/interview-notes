### 1. 100 亿 URL 查询服务

**公司**：腾讯 WXG

**题目**：设计后台服务，加载一个 100 亿个 URL 的文本（每个 URL 最长 400 字节），提供查询接口判断 URL 是否在集合中。

**思路**：
- 100 亿 × 400 字节 ≈ 40 TB，单机不可能全量加载到内存
- **布隆过滤器**：判断"一定不在"或"可能在"
  - 1% 假阳性率 ≈ 只需要约 1.2 GB 的位数组
  - 但布隆过滤器不能删除
- **分片 + 哈希**：用 URL 的 hash 分到多台机器上，每台只存一部分
- **LSM Tree / 磁盘索引**：如果允许毫秒级延迟
- **精确去重方案**：分布式数据库（如 HBase）存 URL hash

### 2. 10 张券 10 万人抢（Redis 热 key）

**公司**：腾讯

**题目**：10 张优惠券被 10 万人抢，Redis 怎么扛住？

**思路**：
- 核心问题：同一个 key（券的库存）被大量并发请求 → 单节点被打爆
- **分 key 打散**：库存预先分到 N 个 key（`coupon:001`、`coupon:002`...），用户随机请求一个 key
- **本地缓存 + 标记位**：大部分请求先被本地缓存挡掉
- **漏斗算法 / 令牌桶**：入口限流
- **MQ 异步削峰**：请求先入队列，后端慢慢处理
- **最终方案组合**：入口限流 + Redis 分 key + 数据库兜底

### 3. 消息队列替代定时轮询

**公司**：人马文化

**题目**：你在定时任务里做了分布式锁和间隔控制，有没有考虑过用消息队列来做？

**思路**：
- 定时轮询的问题：固定间隔可能产生空转、延迟取决于轮询间隔
- 消息队列方案：上游完成时发送消息 → 下游消费后触发处理
- 优点：实时性强、减少空转、解耦
- 缺点：引入新组件、消息可能丢失/重复
- 选型：Kafka 适合高吞吐、RabbitMQ 适合低延迟
- 结论：当前系统的定时扫描方案简单可靠，MQ 方案适合后续优化

### 4. 灰度验证——先小批量再大批量升级

**公司**：币安

**题目**：升级准确性不能保证，怎么先验证再大批量升级？

**思路**：
- 小批量验证：先选 10 台桌面做升级，观察 24 小时
- 逐步放量：10 → 100 → 1000 → 全量
- 暂停条件：出现错误率超过阈值时暂停、自动回滚
- 监控指标：升级成功率、用户反馈、系统负载
- 和灰度发布类似：金丝雀发布 → 分批滚动

### 5. 多模态记忆设计

**公司**：京东

**题目**：以文本为主、少量图片和 PDF 的多模态内容，怎么设计记忆？

**思路**：
- **RAG 场景**：需要检索和召回 → 切片 + Embedding + 向量库
- **直接塞 Prompt 场景**：内容短、一次性使用 → 直接作为上下文
- **渐进式检索**：先粗筛 → 再用 LLM 判断相关性 → 只取最相关的
- **多模态处理**：图片/PDF 先转文本描述（LLM 描述）→ 再存入向量库
- 向量库存的是语义特征，不会存原始大文件

### 6. 前端报错排查

**公司**：币安

**题目**：用户点按钮前端报错了，怎么排查？

**思路**：
- 前端：打开浏览器控制台 → Network 看请求/响应 → Console 看报错信息
- 后端：看日志（请求参数、调用链、异常堆栈）→ 定位问题代码
- 没有工具时：复现 → 二分法缩小范围 → 日志打印关键变量
- 具体排查方向：参数是否合法、接口是否正常返回、下游服务是否正常

### 7. 线上部署要考虑哪些因素

**公司**：人马文化

**题目**：如果让你来负责线上部署，你会考虑哪些因素？

**思路**：
- **资源规划**：CPU/内存/磁盘/网络
- **高可用**：多副本、负载均衡、故障转移
- **可观测**：日志（ELK）、监控（Prometheus/Grafana）、告警
- **发布策略**：灰度发布、回滚机制
- **安全**：防火墙、鉴权、加密
- **容量规划**：预估流量、限流策略

### 8. AI 视频生产系统质量指标

**公司**：美图

**题目**：视频生成出来了，产品上就一定能算成功吗？哪些指标判断系统有没有满足需求？

**思路**：
- **技术指标**：生成成功率、平均耗时、失败率
- **质量指标**：视频画质（分辨率、码率）、音画同步、字幕准确率
- **业务指标**：用户满意度、视频完播率、素材使用率
- **系统指标**：API 调用量、资源消耗、排队时长
- 核心：从"视频生成了"到"用户满意了"之间还有很大差距

### 9. 链路中哪些节点可以用 AI 方法优化

**公司**：币安

**思路**：

- 素材匹配：AI 语义匹配（而非纯标签匹配）

- 质量检测：AI 检测视频瑕疵（画面抖动、音频异常）
- 内容合规：AI 审核内容安全

### 11. 失败经验怎么存、如何避免污染上下文

**公司**：TapTap

**思路**：
- 存为 Markdown + 结构化的 frontmatter（场景、错误、修复、根因）
- 检索时向量匹配：只取与当前任务最相似的 Top-K 条
- 避免污染：不直接拼入 prompt，而是通过 tool 按需查询
- 定期清理：过期的经验自动淘汰或摘要压缩

### 12. 做成平台级门户要完善哪些东西

**公司**：Meshy

**思路**：
- **并发控制**：多用户同时使用时，隔离不同用户的 session 和资源
- **用户隔离**：数据和上下文不互相干扰
- **模型调用限流**：防止某个用户耗尽所有配额
- **KV Cache 管理**：不同用户的 prompt 前缀不同，缓存利用率低
- **权限管理**：不同角色看到不同的功能和数据
- **计费/审计**：用量统计、成本分摊
