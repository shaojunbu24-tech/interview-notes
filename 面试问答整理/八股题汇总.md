## MySQL

### 1. 为什么 MySQL 用 B+ 树做索引？（高频 🔥🔥🔥🔥🔥）

> 问得最多的问题，几乎每场面经都有

**被问公司**：字节跳动 · 美团 · 腾讯(×2) · 小熊博望 · TapTap · 飞轮数据

**核心要点**：
- B+ 树高度低（3-4 层），千万级数据也只需 3-4 次 IO
- 非叶子节点不存数据只存索引 → 每页能存更多 key → 更矮
- 叶子节点形成有序链表 → 范围查询高效（直接遍历叶子链表）
- 相比 B 树：B 树非叶子节点也存数据，每页 key 更少，树更高
- 相比红黑树/AVL：内存中深度小，但磁盘 IO 次数远多于 B+ 树
- 相比 Hash：不支持范围查询，不支持排序

### 2. 哪些情况下索引会失效？（高频 🔥🔥🔥🔥）

**被问公司**：字节跳动 · 美团 · 腾讯(×2)

**核心要点**：
- 最左前缀不满足（联合索引未从最左列开始）
- 对索引列使用函数（`WHERE YEAR(create_time) = 2024`）
- 隐式类型转换（`WHERE id_str = 123`，id_str 是 varchar）
- 索引列参加计算（`WHERE age + 1 = 20`）
- LIKE 以 % 开头（`WHERE name LIKE '%张三'`）
- OR 条件中有非索引列
- MySQL 优化器认为全表扫描比走索引更快（数据量少时）

### 3. 什么是回表？什么是覆盖索引？（高频 🔥🔥🔥🔥）

**被问公司**：美团 · 腾讯

**核心要点**：
- **回表**：InnoDB 二级索引查到主键 ID → 再到聚簇索引查完整行
- **覆盖索引**：索引中已经包含了查询需要的所有字段，不需要回表
- Extra 列中看到 `Using index` 表示走了覆盖索引
- 设计索引时尽量把查询频繁的字段包含进去

### 4. 聚簇索引与非聚簇索引的区别

**被问公司**：字节跳动

**核心要点**：
- **聚簇索引（Clustered Index）**：数据和索引存储在一起，InnoDB 的主键索引就是聚簇的
- **非聚簇索引（Secondary Index）**：索引和数据分开存储，索引叶子存主键值
- InnoDB 必须有聚簇索引（主键 → 第一个唯一键 → 隐藏的 row_id）
- MyISAM 全部是非聚簇索引

### 5. MySQL 存储引擎：MyISAM vs InnoDB

**被问公司**：腾讯 WXG · 腾讯(5.6)

**核心要点**：
| 特性 | InnoDB | MyISAM |
|------|--------|--------|
| 事务 | ✅ 支持 | ❌ 不支持 |
| 行级锁 | ✅ | ❌ 表级锁 |
| 外键 | ✅ | ❌ |
| 聚簇索引 | ✅ | ❌ |
| MVCC | ✅ | ❌ |
| 全文索引 | ✅（5.6+） | ✅ |

### 6. 数据库慢查询的原因有哪些？

**被问公司**：美团

**核心要点**：
- 未走索引或索引失效
- 数据量过大未分页（深分页问题）
- 锁等待（行锁/表锁）
- 不合理的 JOIN / 子查询
- 临时表使用过多（`Using temporary`）
- 单表数据量过大未分区

### 7. 一个查询语句在 MySQL 里是怎么执行的？

**被问公司**：小熊博望

**核心要点**：
`连接器 → 查询缓存(8.0 移除) → 分析器 → 优化器 → 执行器 → 存储引擎`

### 8. 怎么判断一张表需要优化？怎么知道有没有走索引？

**被问公司**：字节跳动

**核心要点**：
- `EXPLAIN` 看 `type`（ALL=全表扫描、range=范围、ref/eq_ref=走索引、const=唯一）
- 看 `rows`（扫描行数）
- 看 `Extra`（`Using filesort`、`Using temporary` 是危险信号）
- 慢查询日志 `slow_query_log` 定位慢 SQL

### 9. 数据库索引怎么设计？为什么选这些字段？

**被问公司**：美团 · 人马文化 · TapTap

**核心要点**：
- 高频查询的 WHERE 字段
- 区分度高的字段在前（联合索引最左前缀原则）
- ORDER BY / GROUP BY 字段
- 索引不是越多越好：写入变慢、占空间、优化器可能选错

## JVM / Java

### 1. Java 垃圾回收机制（高频 🔥🔥🔥🔥）

**被问公司**：远思智能 · 腾讯 · 飞轮数据 · 美图

**核心要点**：
- **分代收集**：新生代（Eden + Survivor）+ 老年代
- **GC 算法**：标记-清除、标记-复制（新生代）、标记-整理（老年代）
- **G1**：Region 化，可设最大停顿时间（`MaxGCPauseMillis`），优先回收垃圾最多的 Region
- **JDK 8 vs 17**：JDK 8 默认 Parallel GC，JDK 9+ 默认 G1，JDK 17 有 ZGC 选项
- **判断存活**：可达性分析（GC Roots），非引用计数
- **判断可回收**：不可达 + `finalize()` 未自救（不推荐使用 finalize）

### 2. 类加载的双亲委派机制

**被问公司**：飞轮数据

**核心要点**：
- Bootstrap ClassLoader → Platform/Extension → Application → Custom
- 子加载器不自己加载，先委派给父加载器
- 父加载器找不到才自己加载
- 安全性：防止核心类被篡改
- 唯一性：`全限定名 + 类加载器` 共同决定类的身份

### 3. 两个类名完全一样的类，什么情况下认为是同一个类？

**被问公司**：飞轮数据

**核心要点**：
- 必须同时满足：全限定名相同 + 由同一个类加载器加载
- 不同类加载器加载的同一个 .class 文件 → `getClass() !=`，各自独立

### 4. JDK 8 和 17 垃圾回收的主要区别

**被问公司**：远思智能

**核心要点**：
- JDK 8：默认 Parallel Scavenge + Parallel Old
- JDK 9+：默认 G1（GC 停顿可预测）
- JDK 11+：ZGC（亚毫秒级停顿，支持 TB 级堆）
- JDK 17：ZGC 生产可用，新增 `-XX:+UseZGC`

### 5. 为什么反射安全管理

**被问公司**：远思智能

**核心要点**：
- 反射可以绕过访问权限检查（`setAccessible(true)`）
- 反射可以访问 private 字段和方法 → 破坏封装性
- SecurityManager 可以限制反射权限（JDK 17+ 已废弃 SecurityManager）

### 6. HashMap 的底层实现原理

**被问公司**：小熊博望

**核心要点**：
- 数组 + 链表 + 红黑树（JDK 8+）
- key 的 hashCode 计算桶位置 → 冲突用链表/红黑树
- 加载因子 0.75，超过阈值（容量 × 0.75）扩容为 2 倍
- 红黑树化阈值：链表长度 > 8 且数组长度 ≥ 64
- 线程不安全（并发 put 可能导致死循环 JDK 7 / 数据覆盖 JDK 8）

### 7. Java 的异常体系

**被问公司**：小熊博望

**核心要点**：
- `Throwable` → `Error`（不可处理，如 OOM、StackOverflow） + `Exception`
- `Exception` → `RuntimeException`（非受检，如 NPE、IndexOutOfBounds）+ 受检异常（如 IOException、SQLException）
- 受检异常必须 try-catch 或 throws 声明
- 异常处理不要吞掉（空 catch），不要用异常做业务控制

### 8. Spring Boot 自动装配原理

**被问公司**：小熊博望

**核心要点**：
- `@SpringBootApplication` = `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan`
- `@EnableAutoConfiguration` 通过 `AutoConfigurationImportSelector` 加载
- 从 spring.factories（2.7 前）或 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 加载自动配置类
- 按条件注解（`@ConditionalOnClass`、`@ConditionalOnMissingBean` 等）决定是否生效

### 9. 为什么反射能破坏安全机制？

**被问公司**：远思智能

**核心要点**：
- `setAccessible(true)` 可以抑制 Java 访问控制检查
- 框架通过反射创建对象、注入字段（Spring IoC）
- 但业务代码不建议滥用

### 10. Java 多线程和并发安全怎么保证？（高频 🔥🔥🔥）

**被问公司**：美图(×2) · 小熊博望

**核心要点**：
- `synchronized` / `Lock` / `volatile` / `CAS` / `Atomic` 类
- 线程池（`ThreadPoolExecutor`）
- `ConcurrentHashMap` / `CopyOnWriteArrayList` 等并发容器

## Redis

### 1. Redis 怎么做分布式锁？（高频 🔥🔥🔥🔥🔥）

**被问公司**：字节跳动 · 美图(×2) · 人马文化 · 美团 · TapTap

**核心要点**：
- `SET key value NX EX timeout`（原子性，同时设置锁和过期时间）
- 不能分开用 `SETNX` + `EXPIRE`（非原子）
- **value 要唯一**（UUID/requestId）→ 释放时校验是否自己的锁
- **释放用 Lua 脚本**：`if redis.call("get", key) == value then return redis.call("del", key) end`
- **过期时间设置**：根据业务执行时间估算，留余量
- **锁续期（看门狗）**：后台线程定期检查并续期（Redisson 实现）
- **Redlock**：多节点场景，向大多数节点加锁（但存在争议，不推荐生产使用）

### 2. 锁超时/续期怎么处理？（高频 🔥🔥🔥🔥）

**被问公司**：字节跳动 · 美图

**核心要点**：
- 锁设置合理超时（如任务平均 3s → 设 5s）
- 看门狗线程（持有锁时每隔 1/3 超时时间续期一次）
- 续期线程如果崩溃：锁自动过期释放，其他实例可以获取
- 续期线程的问题：可能因为 GC 暂停导致续期不及时

### 3. Redis 热 key 问题

**被问公司**：腾讯 · 腾讯 WXG

**核心要点**：
- 热 key 导致单节点 CPU 打满、请求延迟升高
- 热 key 发现：Redis 的 `hotkeys` 参数 / 客户端统计
- 热 key 解决：本地缓存（多级缓存）/ 分片打散（key 加后缀）
- 热 key 在流控中：SETNX 锁对同一个 key 大量并发

### 4. Redis 集群高可用 / 集群挂了怎么办？

**被问公司**：腾讯 WXG

**核心要点**：
- **主从复制**：一主多从，主挂了手动/自动切从
- **哨兵模式**：监控主从，自动故障转移，客户端通过哨兵发现主节点
- **Cluster 模式**：分片 + 自动故障转移，去中心化
- 持久化 + 重启恢复：RDB + AOF
- 集群脑裂：配置 `min-slaves-to-write` + `min-slaves-max-lag` 防止旧主写

### 5. Redis 持久化：RDB vs AOF

**被问公司**：腾讯 WXG

**核心要点**：
| | RDB | AOF |
|--|-----|-----|
| 原理 | 快照（全量） | 追加写命令 |
| 恢复速度 | 快 | 慢 |
| 数据安全性 | 可能丢最后一次快照后的数据 | 可配 everysec/always |
| 文件大小 | 小 | 大 |
| 对性能影响 | fork 子进程（大页时可能卡顿） | 写时追加，可配 rewrite |
| 推荐 | 两者都用 | |

### 6. MySQL 和 Redis 数据一致性怎么保证？

**被问公司**：腾讯

**核心要点**：
- **先更新 DB → 删除/更新 Cache**（Cache Aside 模式）
- 延迟双删：更新 DB → 删 Cache → 延迟 N ms → 再删 Cache
- 最终一致性 vs 强一致性
- 写多读少场景可考虑只读 DB、Cache 降级

## 操作系统

### 1. 进程、线程、协程的区别？（高频 🔥🔥🔥🔥）

**被问公司**：腾讯(×2) · 人马文化

**核心要点**：
| | 进程 | 线程 | 协程 |
|--|------|------|------|
| 资源 | 独立地址空间 | 共享进程空间 | 共享线程空间 |
| 切换 | 内核态（开销大） | 内核态（中等） | 用户态（极快） |

### 2. 什么时候用多进程，什么时候用多线程？

**被问公司**：腾讯(×2)

**核心要点**：
- **多进程**：需要强隔离（不同用户/租户）、稳定性要求高（一个进程崩不影响其他）、CPU 密集型
- **多线程**：频繁共享数据、I/O 密集型、创建销毁频繁
- 举例：Chrome 用多进程（Tab 隔离），Web 服务器用多线程（共享数据）

**被问公司**：人马文化

**核心要点**：同上，注意人马文化投的是 Python 岗位，要额外回答 Python GIL 的影响

## 计算机网络

### 1. TCP 三次握手 / 为什么是三次？（高频 🔥🔥🔥🔥）

**被问公司**：腾讯(×2)

**核心要点**：
1. Client → Server：SYN（seq=x）
2. Server → Client：SYN+ACK（seq=y, ack=x+1）
3. Client → Server：ACK（seq=x+1, ack=y+1）

**为什么不是两次**：两次无法防止已失效的连接请求到达服务器。如果客户端第一个 SYN 延迟很久到达，服务器以为是新连接建立，但客户端已经不发了，浪费服务器资源。三次握手让服务器确认客户端"既能发也能收"。

### 2. TCP 四次挥手 / 为什么是四次？

**被问公司**：腾讯(×2)

**核心要点**：
1. Client → FIN → Server
2. Server → ACK → Client（Server 可能还有数据要发）
3. Server → FIN → Client（Server 数据发完了）
4. Client → ACK → Server

**为什么是四次**：因为 TCP 是全双工的，关闭需要双方各自关闭。第二次和第三次不能合并的原因是：Server 收到 FIN 后可能还有数据要发，等发完再发 FIN。

### 3. 从浏览器输入网址到打开网页的完整流程

**被问公司**：字节跳动

**核心要点**：
1. URL 解析 → DNS 解析（本地 hosts → 递归/迭代 DNS）
2. TCP 三次握手建立连接
3. 发送 HTTP 请求（HTTPS 还需 TLS 握手）
4. 服务器处理请求并返回响应
5. 浏览器解析 HTML（DOM Tree + CSSOM → Render Tree）
6. 布局（Layout）→ 绘制（Paint）
7. 加载子资源（JS/CSS/图片）→ 执行 JS

### 4. 不同地区访问同一个服务，是同一个 IP 吗？

**被问公司**：字节跳动

**核心要点**：
- DNS 解析可能返回不同 IP（GSLB 全局负载均衡）
- CDN 让用户就近接入
- 一套服务多地部署，通过 GSLB 调度到最近的节点

## Kafka / 消息队列

### 1. Kafka 分区怎么用？（高频 🔥🔥）

**被问公司**：远思智能 · 美团

**核心要点**：
- 分区是 Kafka 并行度的基本单位
- 一个分区只能被同一个消费组内的一个消费者消费
- 分区数 = 最大并行消费数
- 消息顺序只能在分区内保证
- key 相同的消息进入同一个分区

### 2. Kafka 怎么保证 ACK？

**被问公司**：远思智能

**核心要点**：
- `acks=0`：不等待确认（可能丢数据）
- `acks=1`：Leader 写入就确认（默认，性能和数据安全的平衡）
- `acks=all`（或 `-1`）：所有 ISR 副本都写入才确认（最强保证，但有延迟）

### 3. Kafka 脑裂怎么解决？

**被问公司**：远思智能

**核心要点**：
- Kafka 用 **Controller** 管理集群，Controller 挂掉后其他 Broker 通过 ZooKeeper 重新选举
- 早期通过 ZK 的临时节点 + Watch 机制实现 Controller 选举
- 从 ZK 迁移到 KRaft（自研 Raft）：去除 ZK 依赖，Controller 用 Raft 共识

### 4. Kafka 从 ZooKeeper 到 Raft 的迁移

**被问公司**：远思智能

**核心要点**：
- 旧版：依赖 ZK 管理元数据和 Controller 选举
- 新版（Kafka 2.8+，3.0 生产可用）：KRaft 模式，用自研 Raft 替代 ZK
- 好处：减少外部依赖、简化运维、提升可用性

### 5. 数据倾斜

**被问公司**：远思智能

**核心要点**：
- 某些分区数据量远大于其他分区
- 原因：key 分布不均匀、分区策略不当
- 解决：重新设计分区 key（加盐/打散）、增加分区数重新平衡

### 6. 如果要实现一个消息队列，你会选什么？

**被问公司**：人马文化

**核心要点**：
- 根据场景选：Kafka（高吞吐、日志、流处理）、RabbitMQ（低延迟、路由灵活）、RocketMQ（事务消息、顺序消息）
- 关键考量：可靠性要求、吞吐量、延迟、消息模型（队列 vs 发布订阅）

## Spring

### 1. Spring AOP 的动态代理原理

**被问公司**：字节跳动

**核心要点**：
- Spring AOP 底层通过动态代理实现
- **JDK 动态代理**：基于接口，目标类必须实现接口 → 生成实现了相同接口的代理类
- **CGLIB 动态代理**：基于继承，生成子类代理 → final 方法和类不能被代理
- Spring Boot 2.x 默认 CGLIB

### 2. Spring AOP 不被 IoC 代理时，切面能生效吗？

**被问公司**：字节跳动

**核心要点**：
- 不能生效。Spring AOP 依赖 IoC 容器的 Bean 管理
- 代理对象由 Spring 容器创建，如果不是 Spring 管理的 Bean，切面不会被织入
- `new` 出来的对象不走 IoC 容器，不会有代理

### 3. Spring Boot 自动装配原理（同上）

**被问公司**：小熊博望

**核心要点**：同 [[八股题汇总#8. Spring Boot 自动装配原理|Spring Boot 自动装配]]

## AI / Agent 基础

### 1. MCP 和 Skills 是什么？（高频 🔥🔥🔥）

**被问公司**：腾讯 · 币安

**核心要点**：
- **MCP（Model Context Protocol）**：标准化协议，让 LLM 通过 Client-Server 调用外部工具和数据源
- 核心原语：Tools（工具）、Resources（资源）、Prompts（提示模板）
- MCP Server 提供能力，MCP Client 让 LLM 调用
- **Skills**：能力包封装，将领域方法论编码为 Skill 文件（SKILL.md）
- 通过 `skill_recall` 渐进披露，按需加载

### 2. LangChain 的用法、节点和边怎么用？

**被问公司**：远思智能

**核心要点**：
- Chain 是核心抽象，用管道语法 `|` 串联
- Agent 通过 Tool + LLM 实现 ReAct 循环
- LangGraph 在图编排上扩展：节点（Node）是任务，边（Edge）是控制流
- 条件边：根据当前状态选择下一个节点

### 3. RAG 框架——用过哪些开源框架？

**被问公司**：京东

**核心要点**：
- LangChain 的 RetrievalQA / 向量检索
- LlamaIndex（侧重数据索引）
- 自建 RAG 管线：Embedding → 向量库 → 检索 → 重排序 → 融合
- 混合检索：向量 + 全文 + 结构化查询

### 4. 上下文压缩和截断会有什么负面影响？

**被问公司**：币安

**核心要点**：
- 压缩可能导致关键信息丢失
- 截断可能砍掉后面的关键内容（因为 prompt 通常把上下文放后面）
- 分层上下文管理：Memory / Tools / Skill / Facts 分层加载
- 用向量检索替代全部传入——只加载与当前任务相关的内容

### 5. Token 优化经验

**被问公司**：腾讯

**核心要点**：
- 渐进披露：先给摘要，需要时再给完整内容
- 上下文分层：只加载当前任务需要的信息
- 消息摘要：用 LLM 压缩早期对话
- prompt 精简：去掉冗余描述
- 控制每次输入的长度（预算管理）
